# Linux：线程同步与线程池

> 上周把「线程怎么建、怎么收」讲完了，这周补上真正难的部分：**多个线程怎么安全地共享状态**，以及把这些零件拼成一个能用的线程池。
> 一条主线：互斥锁保护数据，条件变量/信号量负责「等」，线程池负责「复用」。

## 一、信号量 vs 条件变量：一个数资源，一个等状态

两者都能让线程「等」，但等的东西完全不同：

| | 条件变量 `pthread_cond_t` | 信号量 `sem_t` |
| --- | --- | --- |
| 等什么 | **一个判断条件**（队列非空、任务未完成） | **还有没有额度**（计数 > 0） |
| 是否自带计数 | 否 | 是 |
| 是否必须配锁 | **必须**，条件判断本身要互斥保护 | 不必，`sem_wait`/`sem_post` 本身原子 |
| 典型用途 | 生产者-消费者里「队列空/满」 | 限制并发数、资源池、次序控制 |
| 唤醒语义 | 广播/单播，被唤醒后要**重新检查条件** | 计数减一，减不到就阻塞 |

**为什么条件变量必须配 mutex**：`while (queue_empty) cond_wait(&cond, &mutex);` —— 检查条件和进入等待必须是原子的，否则「检查完为空 → 别人放入任务 → 你才开始等」就会永远等下去。`cond_wait` 在挂起前会原子地释放 mutex，被唤醒后再重新持有，所以检查必须放在锁内。

**实战里最容易错的两件事**（也是我这两周踩到的）：

1. **用 `if` 代替 `while` 判条件**。条件变量可能**虚假唤醒**（spurious wakeup），也可能被广播唤醒但条件已被别的线程抢走。用 `if` 只检查一次，就可能读到空队列。**一律写 `while`。**
2. **信号量忘了配对的 `sem_post`**。`sem_wait` 减一、`sem_post` 加一，少一次 post 就直接把后来的线程锁死，而且不报错。

```c
// 生产者-消费者：条件变量的标准写法
pthread_mutex_lock(&mtx);
while (q_empty(&q))                 // 必须 while，不是 if
    pthread_cond_wait(&not_empty, &mtx);
task = q_pop(&q);
pthread_mutex_unlock(&mtx);
```

## 二、有名信号量 vs 无名信号量：差别只在「找不找得到」

| | 无名 `sem_init` | 有名 `sem_open` |
| --- | --- | --- |
| 生命周期 | `sem_init` → 用 → `sem_destroy` | `sem_open` → `sem_close` → `sem_unlink` |
| 怎么找到它 | **没有名字，只能靠地址传** | 靠 `/name` 汇合，`/dev/shm` 下有实体文件 |
| 跨进程条件 | `pshared` 必须非零，且 `sem_t` 本身必须落在共享内存里 | 天然跨进程，还能设权限（0644） |
| 适用 | 同进程线程间；或已经在共享内存里 | 无亲缘关系的进程之间 |

两个细节：

- **`pshared=0` 是线程间，非 0 才是进程间**。如果 `pshared` 非零但 `sem_t` 放在普通全局变量里，每个进程操作的是各自的副本——**各进程各管各的，看起来「同步没生效」**。
- **`sem_unlink` 只删名字，不删对象**。已经 `sem_open` 的进程继续可用，等最后一个使用者 `sem_close` 后才真正释放。

选型：同进程或已经在共享内存里，用无名（快、少一次名字解析）；跨陌生进程用有名，代价是要管权限和 `unlink`。

## 三、线程池：把任务队列、锁和条件变量拼起来

结构就四样东西：

```
一个链表队列  +  一把 mutex  +  一个 cond  +  N 个常驻 worker
```

### 取任务：锁内出队，空则休眠

```c
void *worker(void *arg) {
    pool_t *p = arg;
    for (;;) {
        pthread_mutex_lock(&p->mtx);
        while (q_empty(&p->q) && !p->shutdown)   // while 防虚假唤醒
            pthread_cond_wait(&p->cond, &p->mtx);
        if (q_empty(&p->q) && p->shutdown) {     // 队列空 且 已关闭 → 退出
            pthread_mutex_unlock(&p->mtx);
            break;
        }
        task_t t = q_pop(&p->q);
        pthread_mutex_unlock(&p->mtx);           // 先解锁
        t.fn(t.arg);                             // 再执行
    }
    return NULL;
}
```

三个关键点：

1. **队列空就 `cond_wait`**，而不是忙等轮询——否则 N 个 worker 空转会烧满 CPU。
2. **先解锁再执行任务**。如果在锁内跑任务，所有 worker 会被串成一条线，线程池退化成单线程，这是最典型的性能 bug。
3. **退出条件是「队列空 **且** 已关闭」**，两个条件缺一不可。只看「队列空」会让池子一空闲就退出；只看「已关闭」会丢掉队列里剩下的任务。

### 任务要带析构回调

```c
typedef struct {
    void (*fn)(void *);
    void *arg;
    void (*destroy)(void *);   // 丢弃任务时用它释放 arg
} task_t;
```

有 `destroy` 才能在「关池时丢弃未执行任务」这条路径上把参数释放干净，否则就是内存泄漏。

## 四、关闭线程池：immediate 与 wait 两个开关

关池不是一个动作，而是两个正交的选择拼出来的四种组合：

| | `wait=1` | `wait=0` |
| --- | --- | --- |
| `immediate=1` | 丢弃队列、立即停，不 join | 丢弃队列、异步 join（cleaner） |
| `immediate=0` | **跑完队列再退**（优雅关闭） | 跑完队列、异步 join |

实现上还要兜住三件事：

1. **丢弃任务时逐个 `destroy(arg)` 再 `free(node)`**，否则参数泄漏。
2. **`wait=0` 时不能在本线程 join**（会阻塞调用者），要交给一个 detached 的 `cleaner` 线程去 join；`cleaner` 创建失败时要退回同步清理，不能直接放弃。
3. **创建 worker 中途失败**（比如第 3 个创建不出来）要回滚：置 `shutdown`、`broadcast` 唤醒已建的、`join` 它们、清空队列、再 `free`。少一步就是泄漏或卡死。

### 一个容易被忽略的设计点

**取任务与执行分两段锁**（锁内出队 → 解锁 → 执行 → 再锁）。这既避免了「锁内跑任务」的串行化，也避免了「拿着锁去 join」的死锁。所有同步代码的性能问题，基本都能从「锁住了什么、锁了多久」这两个角度定位。

## 五、把这一串串起来

```
互斥锁      保护数据，谁改了别人看不见就是 bug
条件变量    等「状态」，必须配 mutex + while
信号量      等「额度」，自带计数，不一定配锁
线程池      以上三者 + 队列 + 生命周期管理（创建回滚 / 关闭四组合）
```

越往下，要自己保证的约束越多：锁只保证互斥不保证顺序，条件变量保证顺序但不保证只唤醒一次，线程池把这两件事封装好，却把「关闭时机」这个最麻烦的问题暴露给你。
