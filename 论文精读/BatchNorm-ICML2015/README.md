# Batch Normalization：把每层输入的「中心」和「尺度」钉住（ICML 2015）

> 一句话：BN 只做三件事——减均值、除标准差、再乘一个可学系数加一个可学偏置；它管用的直接证据是「达到同精度所需步数变少」，但**「消除内部协变量偏移」这个解释后来被推翻了**。

## 一句话总结

前层的参数一变，后层看到的输入分布就跟着变（internal covariate shift）；BN 在每层入口强制把激活拉回零均值、单位方差，再用两个可学参数把表达力还回来，从而允许更大的学习率、更快的收敛。

## 核心贡献

1. **三行公式**：对一批数据按通道算均值与方差 → 归一化 → 乘 γ 加 β。γ、β 可学，保证「归一化」不会削掉网络的表达力。
2. **训练/推理两套统计量**：训练用当前 batch 的均值方差（并参与反传），推理用训练期累积的滑动平均——所以推理时可以折进前面的卷积/线性层，**零额外开销**。
3. **效果**：同结构同数据，加 BN 后达到同一精度所需步数大幅减少，且精度不掉反升。
4. **副作用（论文的意外收获）**：BN 之后对初始化不敏感、可以用更大学习率、某种意义上起到正则作用。

## 方法要点

```
μ_B = mean(x, axis=batch)
σ²_B = var(x, axis=batch)
x̂ = (x − μ_B) / sqrt(σ²_B + ε)
y = γ·x̂ + β
```

- **ε 是数值稳定项**，不是超参；σ 很小时靠它兜底。
- **按通道而不是按样本归一化**：CNN 里是 (N,H,W) 三个维度求统计量、每个通道一组 γβ。
- **推理阶段用 running_mean / running_var**，momentum 默认 0.1 做指数滑动平均。这也是为什么「训练时忘了 `model.eval()`」会让指标不可比——BN 还在用当前 batch 的统计量。

## 实验结论（ImageNet，本页引用论文 Figure 2 的数据）

| 配置 | 达到 72.2% 所需步数（百万） | 相对基线 |
| --- | --- | --- |
| Inception（基线） | 31.0 | 1.0× |
| Inception + BN + lr×5 等 | 13.3 | **2.3×** |
| Inception + BN，论文最终配置 | 2.1 | **14.8×** |

对应精度：72.2% → 73.0% → 74.8%，**不是拿质量换速度**。

### 但这组数字要打三个折

1. **14.8× 是「打包」数字**：它混着七处改动（学习率 ×5、去掉 Dropout、调整权重衰减等），**没有做逐项消融**。能干净归因的只有 2.3×。
2. **「ICS 被消除」只有定性曲线**，没有分布距离（如 KL、MMD）这类量化指标。
3. **单次训练、无多种子**，也没试小 batch——而小 batch 恰恰是 BN 的软肋（batch 太小统计量不稳）。

## 我的思考

1. **BN 管用不等于 BN 的解释成立。** 论文的因果链是「BN → 消除 ICS → 训练更快」，Santurkar 2018 把中间那环拆了：他们人为注入 ICS（让后层输入分布剧烈变化）后发现 BN 依然快，而仅做归一化但不消除 ICS 的版本并没有变慢。**结论是「BN 让优化地形更平滑（Lipschitz 常数更小）」，不是「消除了分布偏移」。** 这提醒我：一个方法有效，和它给出的理由成立，是两件事，要分开验证。
2. **「钉住中心与尺度」管的是形状之外的两阶统计量。** 分布的形状（高阶矩、多峰）BN 管不了——这就是为什么它不能替代好的特征工程。
3. **纸面倍率要按控制变量重算。** 14.8× 里混了学习率 ×5 的收益，2.3× 才是同条件对比出来的。我自己做的优化器实验也是同一个教训：**只有控制住 lr 和轮数，「哪个优化器更好」这句话才有意义。**
4. **本机实验里 BN 的一个直接证据**：手机价格分类任务加 BN 后，前 10 轮就到 90.8%，第 17 轮达到最优 93.75%，之后训练集冲到 98% 而测试集停在 92%——BN 加速收敛非常明显，但它**不会替你解决过拟合**。
