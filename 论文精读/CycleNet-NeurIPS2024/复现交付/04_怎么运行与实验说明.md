## 二、模型原理（30 行代码的核心）

### 2.1 一句话

时间序列里「周期」是确定性的（今天 8 点的用电量 ≈ 昨天 8 点），「趋势和噪声」才是随机的。
CycleNet 用一张**可学习的周期表 Q** 把前者显式建模，让线性主干只去拟合**残差**。

### 2.2 前向计算（`models/CycleNet.py` 的 `forward`）

```
输入 x ∈ ℝ^(B×96×D)，周期索引 t

① Instance Norm   x = (x - mean_t) / sqrt(var_t + 1e-5)
② 减去周期         x = x - Q[t mod W]                    ← RCF 第一步
③ 线性预测         y = Linear(x)                          ← 通道独立，权重共享
④ 加回周期         y = y + Q[(t+96) mod W]                ← RCF 第二步
⑤ 反归一化         y = y * sqrt(var_t) + mean_t
```

`Q ∈ ℝ^(W×D)` 是**逐通道、跨时间全局共享**的一张表：
- W 是周期长度（ETTh1 用 24 = 一天 24 小时；Electricity 用 168 = 一周 168 小时）
- D 是通道数（ETTh1 是 7，Traffic 是 862）
- 第 d 个通道、第 k 个相位的值，就是「该通道在一天/一周中第 k 个时刻的平均水平」

**为什么有效**：主干不必再花容量去重复学同一条曲线，只学「偏离周期的部分」
（天气突变、节假日、随机波动）。于是参数量可以极小。

### 2.3 参数量（这是论文最反直觉的地方）

| 模型 | ETTh1（D=7, H=96）参数量 |
|---|---|
| CycleNet/Linear | **9 480**（周期表 168 + 线性层 9 312） |
| CycleNet/MLP | 99 080（周期表 168 + 两层 MLP） |
| DLinear | 18 624 |
| PatchTST | 千万量级 |

9 480 个参数就能把 ETTh1 的 MSE 做到 0.377，而千万参数的 Transformer 在同一任务上做不到——
**在强周期数据上，正确的归纳偏置比模型容量更值钱**。

### 2.4 与「通道独立」的关系

`Linear` 作用在 `x.permute(0,2,1)` 上，即对每个通道单独做 `96 → H` 的线性映射，**权重共享**。
好处：参数量与通道数只成线性关系（Traffic 862 通道也不爆）；坏处：丢掉了通道间的空间耦合
——这正是论文承认的短板，也是它在 Traffic 上不如 iTransformer 的原因。

## 三、怎么训练一个模型（单配置）

```bash
cd /home/jovyan/work/CycleNet_Repro/CycleNet

python -u run.py \
  --is_training 1 \
  --root_path ../dataset/ \
  --data_path ETTh1.csv \
  --model_id ETTh1_96_96 \
  --model CycleNet \
  --data ETTh1 \
  --features M \
  --seq_len 96 --pred_len 96 \
  --enc_in 7 --cycle 24 \
  --model_type linear \
  --train_epochs 30 --patience 5 --itr 1 \
  --batch_size 256 --learning_rate 0.01 \
  --random_seed 2024 \
  --num_workers 0
```

跑完输出最后一行是 `mse:0.3774, mae:0.3907`，权重存在
`checkpoints/ETTh1_96_96_CycleNet_ETTh1_ftM_sl96_pl96_cycle24_linear_seed2024/checkpoint.pth`。

### 参数说明（改哪个会影响什么）

| 参数 | 含义 | 8 个数据集的官方取值 |
|---|---|---|
| `--data` | 用哪个数据读取器 | ETT 四子集用 `ETTh1/ETTh2/ETTm1/ETTm2`；Weather/Electricity/Traffic 用 `custom`；Solar 用 `Solar` |
| `--data_path` | 文件名（放在 `../dataset/` 下） | 见下表 |
| `--enc_in` | 通道数 | 7 / 7 / 7 / 7 / 21 / 321 / 862 / 137 |
| `--cycle` | **周期长度 W（最关键）** | 24 / 24 / 96 / 96 / 144 / 168 / 168 / 144 |
| `--batch_size` | 批大小 | 256 / 256 / 256 / 256 / 256 / 64 / 64 / 64 |
| `--seq_len` | 回看窗口 L | 主表统一 96 |
| `--pred_len` | 预测长度 H | 96 / 192 / 336 / 720 |
| `--model_type` | 主干 | `linear` 或 `mlp` |

### 8 个数据集的完整对照

| 数据集 | 文件 | `--data` | enc_in | cycle | batch |
|---|---|---|---|---|---|
| ETTh1 | ETTh1.csv | ETTh1 | 7 | 24 | 256 |
| ETTh2 | ETTh2.csv | ETTh2 | 7 | 24 | 256 |
| ETTm1 | ETTm1.csv | ETTm1 | 7 | 96 | 256 |
| ETTm2 | ETTm2.csv | ETTm2 | 7 | 96 | 256 |
| Weather | weather.csv | custom | 21 | 144 | 256 |
| Electricity | electricity.csv | custom | 321 | 168 | 64 |
| Traffic | traffic.csv | custom | 862 | 168 | 64 |
| Solar | solar_AL.txt | Solar | 137 | 144 | 64 |

这些取值不是猜的，来自官方 `scripts/CycleNet/Linear-Input-96/*.sh`。

## 四、怎么批量跑（真正的复现靠这个）

**单配置跑 334 次，不可能靠笔记本一个个点。** 所以有一个调度器：

```bash
cd /home/jovyan/work/CycleNet_Repro

python scripts/run_experiments.py --phase main     --workers 6   # ETT 四子集
python scripts/run_experiments.py --phase new4     --workers 5   # 四个大通道数据集
python scripts/run_experiments.py --phase ablation --workers 6   # RCF / 周期长度
python scripts/run_experiments.py --phase baseline --workers 5   # 同协议基线
python scripts/run_experiments.py --phase mlp8     --workers 5   # MLP × 8 数据集
python scripts/run_experiments.py --phase seeds    --workers 5   # 补 2027/2028
python scripts/run_experiments.py --phase abl_big  --workers 5   # 大通道消融
```

调度器做四件事：
1. **展开配置矩阵**（数据集 × 预测长度 × 种子 × 变体）
2. **多线程并发**调 `run.py`（每个子进程独立训练）
3. **断点续跑**：按 `setting` 字段判重，已完成的自动跳过，中断后重跑不会重复计算
4. **落盘**：每条记录一行 JSON 写进 `results/runs.jsonl`，完整 stdout 写进 `logs/`

### 可以只跑子集

```bash
# 只跑 Weather，只跑 1 个种子
python scripts/run_experiments.py --phase new4 --datasets Weather --seeds 2024 --workers 1
```

### 环境变量（不是可选项）

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
```

容器默认开 4–8 线程时，CycleNet/Linear 的 `(B·C,96)@(96,96)` 小矩阵乘会被线程同步开销拖垮：
**Electricity 单 epoch 从 63 s 降到 6.8 s，数值完全一致**。这个已经写进调度器的 ENV。

## 五、notebook 和脚本到底各管什么（重要）

**一份 notebook 并不跑 8 个数据集。** 两者分工不同：

| | `notebooks/01_CycleNet复现主流程.ipynb` | `scripts/run_experiments.py` |
|---|---|---|
| 定位 | **演示 + 记录**（带解释的流程） | **批量生产**（跑 334 个配置） |
| 跑多少 | 只跑 1 个配置（ETTh1, H=96）做示范 | 全部 |
| 数据 | 打印 8 个数据集的形状与 SHA256 做校验 | 自动选每个数据集的官方超参 |
| 结果 | 读 `runs.jsonl` 汇总、出图、显示在单元里 | 逐条追加写 `runs.jsonl` |
| 耗时 | 约 3 分钟（含 1 次 30 epoch 训练） | 十几个小时（并发） |
| 为什么 | 别人打开就能看懂「怎么跑」 | 长任务不能占着 kernel 串行跑 |

所以正确用法是：**先用 notebook 走一遍理解流程，再用调度器批量跑数据。**

notebook 里另外 6 个代码单元做的是：环境自检、锁代码版本、校验 8 个数据文件、
读 `runs.jsonl` 做统计、跑 `analyze.py`、跑 `make_figures.py` + `plot_learning.py`
（后两个单元会把 10 张图直接内嵌显示）。
