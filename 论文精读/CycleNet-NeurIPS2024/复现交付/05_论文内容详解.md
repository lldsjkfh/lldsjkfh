> 华南理工大学 / 鹏城实验室 / 香港中文大学 / 暨南大学 · NeurIPS 2024（第 38 届）

这份文档按「**要解决什么问题 → 想达到什么目的 → 为什么这么做 → 怎么做 → 证据**」的顺序展开，

## 1 要解决的问题

### 1.1 长程预测的根本困难：近期信息不够用

时间序列预测（TSF）在气象、交通、能源管理里都是刚需。而当预测长度拉到
**96–720 步**（几天到几个月）时，问题的性质就变了：

> 一个用户 30 天后的用电量，不只取决于他最近几天的用电量。

短程预测可以靠「近期均值 + 趋势」外推；长程预测不行——误差会指数式累积，趋势项早已失效。
论文指出，真正支撑长程预测的是**数据内部稳定的周期性**：
只要知道「这个人每天 8 点起床、每周三加班」，就能把 30 天后的基线画出来。

### 1.2 现有做法：用复杂度去「逼近」周期

既然周期是关键，主流模型的做法是**增强模型提取长程依赖的能力**，从而间接把周期学出来：

| 路线 | 代表 | 手段 |
|---|---|---|
| Transformer | Informer / Autoformer / PatchTST | 自注意力的长距离建模 |
| CNN | ModernTCN | 大卷积核扩大感受野 |
| RNN | SegRNN | 分段迭代处理长序列 |

这条路线的隐含逻辑是：**「只要模型够强、能看到足够长的历史，周期自然会被学到。」**

### 1.3 论文指出的矛盾

论文用一个反问把这个逻辑掀开了（原文引言）：

> However, if the purpose of constructing deep and complex models is solely to better extract
> periodic features from long-range dependencies, **why not directly model the patterns?**

你花 1070 万参数、25.87G MACs 去「学」一条本来就能画出来的日周期曲线，
这笔账划算吗？

### 1.4 三条具体的痛点

论文没有停在反问上，而是指出了现有方案三个可验证的缺陷：

**痛点 1：容量浪费在重复学习同一条曲线。**
对强周期数据，序列里 60%–80% 的方差由周期解释。Transformer 的每一层、每个注意力头，
都在反复拟合同一条形状。参数花在了「记住」而不是「预测」上。

**痛点 2：窗口内的 STD 分解有两个固有缺陷。**
STD（Seasonal-Trend Decomposition）是 DLinear / Autoformer / FEDformer 的标准做法：
用滑动平均把序列拆成「季节项 + 趋势项」。论文指出它有两个硬伤：

- **滑动窗口必须大于季节分量的最大周期**，否则分解不完整；
  更极端的情况是——**周期长度超过回看窗口长度时，分解根本无法进行**（L=96 想分解周周期 168？做不到）
- **序列边缘需要零填充**才能得到等长的移动平均序列，这会造成边缘失真

**痛点 3：窗口内分解在理论上等价于线性回归。**
论文给了一个很锋利的论证（原文 4.4 节）：

> 这些在回看窗口内解耦趋势与季节性的方法，本质上等价于**无约束或弱约束的线性回归**。
> 也就是说，训练充分收敛后，基于线性骨干 + 这类分解的模型，**理论上等价于纯线性模型**。

这句话的意思是：DLinear 看起来在做分解，但它能表达的函数空间并没有跳出「线性映射」。
**它永远无法超越有限回看窗口的信息边界**——想让模型知道「上周同一时刻」发生了什么，
就必须把窗口拉到一周以上，而窗口一长，Transformer 的训练成本就爆炸。

## 2 想达到的目的

论文的目标可以拆成三层，每一层都有明确的判据：

| 层级 | 目的 | 判据 | 论文结果 |
|---|---|---|---|
| 直接目的 | **显式建模周期**，把周期从「要学的隐特征」变成「可解释的参数」 | 能画出来、能验证 | 图 4 可视化出日/周曲线，与真实模式对应 |
| 性能目的 | 在 LTSF 基准上达到 SOTA | 8 个数据集、4 个预测长度的平均 MSE | CycleNet/MLP 综合第一，Linear 第二（Traffic 除外） |
| 效率目的 | 参数量降一个数量级以上 | 与 iTransformer / PatchTST 对比 | 参数减少 **90%+**，RCF 模块 **0 额外 MACs** |
| 外溢目的 | 做成**即插即用**模块，能提升已有模型 | 接到 PatchTST / iTransformer / DLinear 上 | 提升 5%–20% |

最后一条是这篇论文容易被低估的地方：它不只提出一个模型，还提出了一个**可以装到别人模型上的技术**。

## 3 这么做的原因

### 3.1 数据层面的原因：周期是确定性的，残差是随机的

这是整个方法的立论基础。把一条序列拆成两部分：

```
x(t) = c(t) + r(t)
       ↑      ↑
    周期分量   残差
   （确定性）  （随机：天气、节假日、突发事件）
```

- `c(t)` 对同一相位几乎不变 → 可以**用一张表查出来**，不需要模型去「学」
- `r(t)` 才是真正需要模型预测的部分

因此论文把任务改写成：**先扣掉 c(t)，让模型只预测 r(t)，最后再把 c(t) 加回去。**
模型的负担从「预测整条曲线」降到「预测偏离周期的部分」，难度大幅下降。

### 3.2 模型层面的原因：归纳偏置 > 模型容量

深度学习的常识是「容量越大拟合能力越强」，但这条在强周期数据上失效：

- 周期是**结构化的先验**，把它写进结构里，等于免费送给模型一大批正确信息
- 用容量去「学」一个已知的先验，是低效的——需要大量数据、大量参数、大量算力，还学不准

论文的实证支持：CycleNet/Linear 用 **123.7K 参数**（Electricity, H=720）就把
MSE 做到 0.141，而 12.53M 参数的 Informer 是 0.227。
**参数量差 100 倍，效果还更好。**

### 3.3 为什么主干选 Linear / MLP（不是随便挑的）

扣掉周期之后，剩下的残差 `r(t)` 有两个特点：

1. **近似零均值、无强周期** → 不需要复杂的时序建模能力
2. **通道之间统计特性不同** → 需要逐通道处理，但不能让参数量随通道数爆炸

于是：
- **单层 Linear**：`96 → H` 的线性映射，逐通道、权重共享。参数量 `96×H`，与通道数 D 无关
- **双层 MLP**：`96 → 512 → H`，加一层非线性。在高维数据集（Electricity 321、Solar 137）上更好，
  因为通道独立策略下，非线性映射能力对高维数据是必要的

**这就是「通道独立」（Channel Independent）的由来**：不是为了省参数才这么做，
而是因为残差建模本身不需要跨通道交互——周期部分已经逐通道建模了。

### 3.4 为什么是「全局周期表」而不是「窗口内分解」

这是 RCF 与所有 STD 方法的**本质区别**，也是它能突破痛点 3 的原因：

| | 窗口内 STD（DLinear 等） | 全局周期表（RCF） |
|---|---|---|
| 周期从哪来 | 当前这个回看窗口内，用滑动平均估 | **整个训练集**上学习得到，跨样本共享 |
| 能看多远 | 受限于窗口长度 L | 不受限（全局统计量） |
| 参数 | 无可学参数 | `W×D` 个可学参数 |
| 表达能力 | 等价于线性回归 | 超越线性回归（周期项是非线性查表） |

一句话：**DLinear 是「看着最近 96 步猜周期」，RCF 是「把整个训练集的周期背下来」。**

论文的实证（Table 5，统一 L=336、不加归一化）也印证了这一点：

| 数据集 | CLinear（RCF） | DLinear（MOV） | SLinear（Sparse） | 纯 Linear |
|---|---|---|---|---|
| Electricity | **0.157** | 0.167 | 0.172 | 0.167 |
| Solar | **0.220** | 0.254 | 0.255 | 0.253 |
| Traffic | **0.423** | 0.434 | 0.435 | 0.434 |
| ETTm1 | **0.349** | 0.367 | 0.362 | 0.362 |
| Weather | 0.245 | 0.244 | 0.246 | 0.245 |

注意后两行：**在周期性弱的 Weather 上，RCF 与纯线性打平，其他 STD 方法甚至不如纯线性。**
这恰好说明：STD 类方法在周期弱时是「白折腾」，而 RCF 至少不会变差（最坏退化成无 RCF）。

## 4 解决问题的方法

### 4.1 整体结构

```
        输入 x (L×D)
            │
      ┌─────▼─────┐
      │ Instance  │  减去窗口均值、除以标准差
      │   Norm    │
      └─────┬─────┘
            │  x_norm
      ┌─────▼─────────────────────┐
      │  ② 减去周期分量 c(t)       │  ← RCF 第一步
      │     x' = x_norm - Q[t mod W]
      └─────┬─────────────────────┘
            │  x'
      ┌─────▼─────┐
      │  Linear   │  逐通道、权重共享（通道独立）
      │  或 MLP   │  96 → H
      └─────┬─────┘
            │  ŷ'
      ┌─────▼─────────────────────┐
      │  ④ 加回周期分量 c(t+L)     │  ← RCF 第二步
      │     ŷ = ŷ' + Q[(t+L) mod W]
      └─────┬─────────────────────┘
            │
      ┌─────▼─────┐
      │ 反归一化   │
      └─────┬─────┘
            │  预测 ŷ (H×D)
```

### 4.2 RCF 的两步

**第一步：建模周期。**
给定 D 个通道、先验周期长度 W，构造一张可学参数表 `Q ∈ ℝ^(W×D)`，**初始化为全零**。
这张表在通道内全局共享：通过循环复制，就能得到与序列等长的周期分量 `C`。

关键点：`W` 由数据的**先验特性**决定，应取数据中**最大的稳定周期**。
论文给了两种确定方式：
- 按采样频率直接推（1 小时采样的日周期 = 24；15 分钟的日周期 = 96）
- 用**自相关函数（ACF）**验证（论文附录 B.2）

**第二步：残差预测。**

1. 从输入 `x` 中减去周期分量 `c`，得到残差 `x'`
2. 残差过主干（Linear / MLP），得到残差预测 `ŷ'`
3. 把 `ŷ'` 加回输出段的周期分量 `c(t+L)`，得到最终预测

### 4.3 一个工程细节：怎么"对齐并重复"周期表

`c(t)` 是一条"虚拟序列"，不能直接切片，必须从 `Q` 里取：

1. **左移（Roll）** `Q` 共 `t mod W` 位，得到 `Q^(t)`。这里 `t mod W` 就是当前样本在周期表中的相对相位
2. **重复并拼接**：`Q^(t)` 重复 `⌊L/W⌋` 次，再接上 `Q^(t)[0 : L mod W]`

数学形式（论文式 1、2）：

```
c[t-L+1 : t]   = [ Q^(t), …, Q^(t),  Q^(t)[0 : L mod W] ]
                   └── ⌊L/W⌋ 次 ──┘

c[t+1 : t+H]   = [ Q^(t+L), …, Q^(t+L),  Q^(t+L)[0 : H mod W] ]
                     └── ⌊H/W⌋ 次 ──┘
```

仓库里的实现用**索引算术 + 取模**一次 gather 完成（PR #4 的贡献），比最初的手写 roll+repeat 快 2–3 倍：

```python
gather_index = (index.view(-1,1) + torch.arange(length).view(1,-1)) % cycle_len
return self.data[gather_index]
```

### 4.4 Instance Normalization

时间序列的均值、方差随时间漂移（distribution shift），训练集上学的模型用到未来数据会失准。
CycleNet 采用与 RevIN **去掉可学仿射参数**的版本：

```
x_norm = (x - μ) / sqrt(σ + ε)          ← 输入侧
ŷ      = ŷ_norm × sqrt(σ + ε) + μ       ← 输出侧
```

μ、σ 是**当前窗口**的均值和标准差。注意这一步在 RCF 之前，所以周期表学的是"归一化之后"的周期形状。

### 4.5 损失函数

保持与主流一致，用 MSE：

```
Loss = ‖ x[t+1 : t+H] − ŷ[t+1 : t+H] ‖²₂
```

### 4.6 代价：几乎没有

| 项 | 额外开销 |
|---|---|
| 参数 | 仅 `W × D`（Electricity: 168 × 321 = **53.9K**） |
| 计算 | **0 额外 MACs**（只是查表和加减法） |
| 内存 | 一张 `W×D` 的表 |

论文 Table 3（Electricity, L=96, H=720）：

| 模型 | 参数量 | MACs | 每 epoch 训练时间 |
|---|---|---|---|
| Informer | 12.53M | 3.97G | 70.1 s |
| PatchTST | 10.74M | 25.87G | 129.5 s |
| iTransformer | 5.15M | 1.65G | 35.1 s |
| DLinear | 139.6K | 44.91M | 18.1 s |
| **CycleNet/Linear** | **123.7K** | **22.42M** | 29.6 s |
| **CycleNet/MLP** | **472.9K** | **134.84M** | 30.8 s |
| （其中 RCF 模块） | 53.9K | **0** | 12.8 s |

一个诚实的细节：CycleNet 比 DLinear 慢（29.6 vs 18.1 s），
因为对齐周期表要逐样本做 CPU 侧的索引运算。论文如实写了这点。

## 5 方法的证据

### 5.1 主结果（Table 2，L=96，4 个预测长度平均 MSE / MAE）

| 数据集 | CycleNet/Linear | CycleNet/MLP | iTransformer | PatchTST | DLinear |
|---|---|---|---|---|---|
| ETTh1 | **0.432** / 0.427 | 0.457 / 0.441 | 0.454 / 0.447 | 0.469 / 0.454 | 0.456 / 0.452 |
| ETTh2 | 0.383 / 0.404 | 0.388 / 0.409 | 0.383 / 0.407 | 0.387 / 0.407 | 0.559 / 0.515 |
| ETTm1 | 0.386 / 0.395 | **0.379** / 0.396 | 0.407 / 0.410 | 0.387 / 0.400 | 0.403 / 0.407 |
| ETTm2 | 0.272 / 0.315 | **0.266** / 0.314 | 0.288 / 0.332 | 0.281 / 0.326 | 0.350 / 0.401 |
| Electricity | 0.170 / 0.260 | **0.168** / 0.259 | 0.178 / 0.270 | 0.205 / 0.290 | 0.212 / 0.300 |
| Solar | 0.235 / 0.270 | **0.210** / 0.261 | 0.233 / 0.262 | 0.270 / 0.307 | 0.330 / 0.401 |
| Traffic | 0.485 / 0.313 | 0.472 / 0.301 | **0.428** / 0.282 | 0.481 / 0.304 | 0.625 / 0.383 |
| Weather | 0.254 / 0.279 | **0.243** / 0.271 | 0.258 / 0.278 | 0.259 / 0.281 | 0.265 / 0.317 |

两个观察：

- **CycleNet/MLP 综合第一，Linear 第二。** MLP 在高维数据集（Electricity 321、Solar 137）上更强，
  因为通道独立策略下，非线性映射能力对高维数据是必要的
- **Traffic 是唯一输给 iTransformer 的**（0.485 vs 0.428）。论文自己解释了原因：
  Traffic 有强时空耦合（某个检测点的车流会影响邻近点），而 CycleNet 逐通道独立建模，
  丢掉了通道间关系。但即便如此，它仍显著优于其他所有基线

### 5.2 RCF 到底贡献了多少（Table 4，H=96）

| 骨干 | Electricity 无 RCF | + RCF | 提升 | Traffic 无 RCF | + RCF | 提升 |
|---|---|---|---|---|---|---|
| Linear | 0.197 | **0.141** | **28.6%** | 0.645 | **0.480** | **25.6%** |
| MLP | 0.175 | **0.136** | 22.2% | 0.500 | **0.458** | 8.5% |
| DLinear | 0.195 | **0.143** | 26.6% | 0.649 | **0.506** | 22.1% |
| PatchTST | 0.168 | **0.136** | 19.0% | 0.436 | 0.438 | −0.5% |
| iTransformer | 0.148 | **0.136** | 8.1% | 0.395 | 0.415 | −5.1% |

三个结论：

1. **给最简单的主干加 RCF，提升 10%–29%** → CycleNet 的成功主要来自 RCF，不是骨干、也不是归一化
2. **RCF 是即插即用的**：接到 DLinear（已有 STD）仍有 26.6%，接到 PatchTST 有 19.0%
3. **但也暴露了边界**：在 Traffic 上给 PatchTST / iTransformer 加 RCF，**MSE 反而变差**
   （MAE 改善）。论文解释是 Traffic 存在极端值，而 RCF 本质是学「历史平均周期」，
   平均值会被极值带偏。这一点论文没有回避，反而作为未来方向

### 5.3 W 必须对（Table 6，H=96，MSE）

| 数据集 | 正确 W | 正确值 | W=168 | W=144 | W=96 | W=24 | 无 RCF |
|---|---|---|---|---|---|---|---|
| Electricity | 168 | **0.142** | 0.142 | 0.196 | 0.196 | 0.195 | 0.197 |
| Traffic | 168 | **0.480** | 0.480 | 0.617 | 0.617 | 0.618 | 0.645 |
| Solar | 144 | **0.208** | 0.289 | 0.208 | 0.276 | 0.287 | 0.286 |
| ETTm1 | 96 | **0.325** | 0.350 | 0.340 | 0.325 | 0.348 | 0.351 |
| ETTh1 | 24 | **0.377** | 0.395 | 0.384 | 0.383 | 0.377 | 0.384 |

**只有正确的 W 才有收益；W 设错时，效果退化到「等于没用 RCF」。**
这是理解 RCF 本质的关键：它不是「多几个可学参数」的正则化技巧，
而是**依赖先验周期与数据真实周期匹配的结构性设计**。

好消息是：W 设错不会比不用 RCF 更差（最坏情况打平）。

### 5.4 学到了什么（Figure 4）

训练完成后，`Q` 会从全零变成有形状的曲线：

- Solar 的第 137 通道 → 光伏发电的**日内**形状（夜间为 0，正午峰值）
- Traffic 的通道 → **周内**形状（工作日早高峰）
- Electricity 不同通道 → 同样是日周期，但**形状各异**，有的工作日间歇、有的平稳

最后一点证明「**逐通道建模是必要的**」——同一个数据集里，不同用户的用电行为并不一样。

## 6 论文承认的局限（Discussion）

论文自己列了四条，都很实在：

| 局限 | 说明 |
|---|---|
| **周期长度不稳定** | 只学固定长度周期，不适合周期随时间变化的数据（如心电图 ECG） |
| **各通道周期长度不同** | 默认所有通道用同一个 W；可行解是按周期长度分组预处理，或逐通道当独立数据集建模 |
| **对异常值敏感** | RCF 学的是「历史平均周期」，显著异常值会把均值拉偏，进而污染周期项与残差项 |
| **长周期（年周期）建模困难** | 理论上 W 可以设为一年，但需要几十年的数据才能训练出一个完整的年周期 |

未来方向：**如何把 RCF 与通道间关系建模结合**。
论文坦言，直接把 RCF 套到 iTransformer 上在 Traffic 上 MSE 没改善（Table 4 的 −5.1%），
说明「周期建模」和「空间耦合建模」还没能优雅地融合。

## 7 一句话总结这篇论文

**它指出了一个被忽视的常识：长程预测靠的是周期，而周期本来就在数据里、可以被直接查表。
于是它把「用深模型学周期」换成了「把周期扣掉、只学残差」，
用 10 万级参数打赢了千万级 Transformer，并把这件事做成了一个能装到别人模型上的模块。**

这也解释了它为什么能拿 NeurIPS Spotlight：
**它不是又一个更强的模型，而是一个更正确的视角。**
