# 损失函数与优化器：两组实测对比

> 本周的核心不是「知道有哪些损失/优化器」，而是**在控制变量的前提下量出差距**。
> 两组实验都是本机 CPU 单种子实测，数字与 PPT 一致；代码目前只在本地，未开源。

## 一、损失函数：回归看误差形状，分类看交叉熵

| 损失 | 形式 | 特点 |
| --- | --- | --- |
| MSE | `e²` | 对大误差惩罚重、处处可导，最常用 |
| MAE | `\|e\|` | 对离群点稳健，但 **0 点不可导** |
| SmoothL1 | `\|e\|<1` 用 `0.5e²`，否则 `\|e\|−0.5` | 小误差像 MSE、大误差像 MAE |
| 交叉熵 | `−log(softmax 正确类)` | 梯度 = `p − y`，配 logits 使用 |

**一个误差，两种罚法**：`e = 3` 时 MSE 罚 9，MAE 只罚 3——这就是 MSE 对离群点敏感的原因，也是「有离群点就换 MAE / SmoothL1」的由来。

**分类的两个坑**：
1. `CrossEntropyLoss` **内部已含 softmax**，模型最后一层不要再加 `Softmax`，否则等于做了两次。
2. 交叉熵要配 **logits**（未归一化输出）算，数值更稳；先 softmax 再取 log 容易下溢。

选型：数据有离群点用 MAE / SmoothL1，否则 MSE；分类一律交叉熵。

## 二、优化器：从「只看一步」到「看趋势 + 看尺度」

| 优化器 | 更新规则 | 解决什么 |
| --- | --- | --- |
| SGD | `θ ← θ − η·g` | 只看当前梯度，峡谷地形上震荡明显 |
| Momentum | `v ← βv + ηg`，`θ ← θ − v` | 加惯性，抹平方向上的来回震荡 |
| Adagrad | `θ ← θ − η·g / √(Σg²)` | 每个参数自己的步长，但分母只增不减 → 后期停走 |
| RMSprop | 把 `Σg²` 换成指数滑动平均 | 解决 Adagrad 的「步长衰减到 0」 |
| Adam | 一阶矩 + 二阶矩 + 偏差修正 | 方向与尺度都自适应，通常最省心 |

一句话：**SGD 是「当前位置」，Momentum 加「速度」，Adagrad 系列加「每个参数自己的步长」。**

一个常被误解的点：**震荡来自方向，不是步长**。所以在峡谷地形上单纯调小学习率没用，要改的是「用哪个梯度」——这也解释了为什么下面同 lr 下差距能有 10–25 倍。

## 三、实验一：五种优化器对比（digits 手写数字）

**设置（控制变量）**

| 项 | 值 |
| --- | --- |
| 数据 | digits 1797 张，8×8 灰度，10 类；70/30 划分 = 1257 / 540 |
| 模型 | 64 → 32(tanh) → 10，**2410 参数** |
| 训练 | 全批量、300 epoch、`lr=0.01`（**所有优化器相同**）、CPU、单种子 |

**结果**

| 优化器 | 最终准确率 | 到 90% 的 epoch | 末轮 loss |
| --- | --- | --- | --- |
| SGD | 0.6019 | 未达到 | 2.04 |
| Momentum | 0.9278 | 228 | 0.35 |
| Adagrad | 0.9426 | 59 | 0.22 |
| RMSprop | **0.9648** | **12** | **0.002** |
| Adam | 0.9630 | 23 | 0.006 |

**结论**：同样 `lr=0.01`，RMSprop 12 轮达标，SGD 跑满 300 轮仍在 60%——差的是「怎么用梯度」，不是调参。
最终准确率上 RMSprop 与 Adam 只差 0.18 个点，但**达到 90% 的轮数差了近一倍**（12 vs 23），所以「谁更快」和「谁更准」要分开看。

## 四、实验二：手机价格分类（20 维表格 → 四档）

**设置**

| 项 | 值 |
| --- | --- |
| 数据 | 2000 × 20，四档各 500，8:2 划分（训练 1600） |
| 模型 | 20 → 128 → 64 → 4，**BN + Dropout 0.3**，11.6 K 参数 |
| 训练 | 50 epoch，batch 32，Adam `1e-3` |

**读数**

- 前 10 轮就到 **90.8%**（BN 的加速效果很明显），之后缓慢爬升；
- 最优 **93.75%（第 17 轮）**，末轮回落到 92.0%；
- 训练集 98% 对测试集 92% —— **30 轮之后已经过拟合**。

**两个必做项**（不做实验就白跑）：

1. **标准化**：20 维量纲差异极大，不做等于只用 `ram` 一个特征（手机价格主要由内存决定）。
2. **评估前 `model.eval()`**：否则 BN 用当前 batch 的统计量、Dropout 还在随机丢，指标不可比。

## 五、过拟合诊断：gap 压下去了，但精度没怎么涨

**为什么会过拟合**

- 1600 个训练样本对 11588 个参数，**参数/样本 ≈ 7.2**，模型记得住训练集；
- BN 让前 20 轮就收敛，之后训练集涨到 98%，涨的主要是噪声；
- 价格本来就主要由 `ram` 决定，其余 19 维信息量有限——**这是任务的天花板，不是模型的错**。

**三种正则做法（3 种子均值）**

| 配置 | 测试准确率 | train-test gap |
| --- | --- | --- |
| Dropout 0.3（基线） | 91.6% | 5.0 点 |
| Dropout 0.5 | 92.0% | 4.0 点 |
| 加 L2 `1e-4` | 91.4% | 基本没动 |
| Dropout 0.5 + L2 | 91.9% | **3.8 点（最小）** |

**判断**：过拟合是真的，但**不是这个任务的瓶颈**——正则能把 gap 从 5.0 压到 3.8，绝对精度只动 0.4 个点。要再往上涨，得从**特征和数据量**下手，而不是继续加正则。
L2 基本无效也说明一件事：**正则手段要对症**，L2 压的是权重大小，压不住「参数远多于样本」这种容量错配。

## 六、两组实验的方法论

1. **优化器实验控住了 lr 和轮数**，所以「同样 lr 下差 10–25 倍」这句话才成立；否则只是调参水平的差异。
2. **正则实验控住了模型、数据、训练轮数**，只改正则配置，所以 gap 的变化能归因到正则本身。
3. **单种子是这组实验最大的短板**——优化器那张表只有一次运行，准确率的小数位不应过度解读（所以结论只敢说「量级差」，不敢说「RMSprop 一定优于 Adam」）。
